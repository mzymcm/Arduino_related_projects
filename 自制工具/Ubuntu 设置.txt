Ubuntu 设置

1. 安装SSH服务器
sudo apt update
sudo apt install openssh-server
2. 编辑SSH配置文件
sudo nano /etc/ssh/sshd_config
3. 允许root登录
在配置文件中找到PermitRootLogin行，并将其更改为yes：
PermitRootLogin yes
3. 重启SSH服务
sudo systemctl restart sshd



安装并配置XRDP服务
对于旧版Ubuntu，或者希望获得更稳定、类似Windows服务器远程连接体验的用户，xrdp是首选。
sudo apt update
sudo apt install xrdp -y
安装完成后，xrdp服务会自动启动。运行以下命令确保它开机自启：
sudo systemctl enable --now xrdp

要修改 gnome-remote-desktop 的默认 3389 端口，可以使用 gsettings 命令来完成。以下是具体步骤：
gsettings set org.gnome.desktop.remote-desktop.rdp port 23389
这个修改会立即生效，不需要重启服务 。
根据 GNOME 官方提交记录，从 2023 年 11 月开始，gnome-remote-desktop 的 RDP 端口已经改为通过 gsettings 配置，不再是硬编码的 3389 。
修改端口后，需要关闭再重新打开桌面共享功能：
systemctl --user restart gnome-remote-desktop
检查新端口是否已监听：
ss -tuln | grep 23389
防火墙放行新端口
如果开启了 UFW 防火墙，需要放行新端口：
sudo ufw allow 23389/tcp


如果之前已经停止/禁用了 gnome-remote-desktop 服务，这个配置可能不会立即生效。你需要重新启用它：
systemctl --user enable --now gnome-remote-desktop
与 xrdp 的端口冲突问题：如果你是因为 xrdp 需要 3389 端口而修改 gnome-remote-desktop 的端口，那么修改后两个服务可以共存（一个用 3389，一个用 23389），互不干扰。
配置文件位置：这个设置存储在用户的 dconf 数据库中，对应路径为 /org/gnome/desktop/remote-desktop/rdp/port 。
如果你修改后遇到任何问题，或者需要改回 3389 端口，只需执行：
gsettings set org.gnome.desktop.remote-desktop.rdp port 3389




安装与重新安装docker

1️⃣ 彻底卸载 Docker
1.1 停止所有运行中的容器
docker stop $(docker ps -aq) 2>/dev/null
1.2 删除所有容器、镜像、卷和网络（可选，但推荐）
# 删除所有容器
docker rm $(docker ps -aq) 2>/dev/null
# 删除所有镜像
docker rmi $(docker images -q) 2>/dev/null
# 删除所有未使用的卷
docker volume prune -f
# 删除所有未使用的网络
docker network prune -f
1.3 卸载 Docker 软件包
apt purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
1.4 删除 Docker 的残留目录和文件
rm -rf /var/lib/docker
rm -rf /var/lib/containerd
rm -rf /etc/docker
rm -rf /etc/apt/sources.list.d/docker.list
rm -rf /usr/share/keyrings/docker-archive-keyring.gpg
1.5 （可选）删除 docker 用户组
groupdel docker 2>/dev/null
2️⃣ 重新安装 Docker


apt clean
apt update

apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin


启动 Docker 并验证
systemctl start docker
systemctl enable docker


清除命令哈希缓存
在终端中执行以下命令，清除 Bash 记住的命令路径：
hash -r


docker --version
测试运行
docker run hello-world


确保 Docker 服务正确重启
修改配置文件后，必须执行以下命令使配置生效：
systemctl daemon-reload
systemctl restart docker
执行 restart 后，可以查看服务状态确认是否正常运行：
systemctl status docker
3. 验证当前生效的镜像加速器
重启后，使用 docker info 命令查看实际生效的配置：
docker info | grep -A 1 "Registry Mirrors"
如果输出中显示的 Registry Mirrors 地址仍然是旧的 ewbrw0qv...，说明配置确实没改过来；如果显示的是新的地址（或无地址），则问题已解决。

测试  /etc/docker/daemon.json 的格式正确性

file /etc/docker/daemon.json

查看 Docker 服务日志中关于配置加载的信息
journalctl -u docker.service --since "5 minutes ago" | grep -i config
这能显示 Docker 启动时是否有读取配置文件的记录，或是否有任何错误。

检查是否有 systemd override 文件覆盖了 Docker 的启动参数
ls -la /etc/systemd/system/docker.service.d/
如果有这个目录且包含 .conf 文件，Docker 的启动参数可能被修改，例如通过环境变量指定了镜像加速器。

检查 /etc/default/docker 文件（旧版 Docker 常用配置）
cat /etc/default/docker
如果存在，可能在其中设置了 DOCKER_OPTS 包含了镜像加速器。

检查 /etc/docker/daemon.json 的权限
ls -l /etc/docker/daemon.json
确保权限至少为 -rw-r--r--（644），且所有者是 root。

重启 Docker 服务并立即验证配置
systemctl restart docker
docker info | grep -A 1 "Registry Mirrors"
如果重启后依然显示旧地址，尝试清除 Docker 的配置缓存（如有）并彻底重置

在Linux上安装Portainer CE
docker volume create portainer_data

docker run -d -p 8000:8000 -p 9443:9443 --name portainer --restart=always -v /var/run/docker.sock:/var/run/docker.sock -v portainer_data:/data portainer/portainer-ce:sts

登录
安装完成后，您可以通过打开网页浏览器并访问以下网站登录您的 Portainer 服务器实例：
https://localhost:9443
如果需要，用相应的IP地址或FQDN替换，如果之前改过端口，请调整。localhost
你会看到Portainer服务器的初始设置页面。

如果你已经创建过但忘记了密码
如果你之前已经设置过密码，但现在忘记了，可以通过 Docker 命令来重置。Portainer 官方提供了一个很方便的密码重置辅助工具。

你需要 SSH 登录到你的 Ubuntu 服务器，然后执行以下步骤：

停止 Portainer 容器（请将 portainer 替换为你的容器实际名称）：
docker stop portainer
运行密码重置助手。这个命令会为 admin 用户生成一个新的随机密码并显示在屏幕上 ：
docker run --rm -v portainer_data:/data portainer/helper-reset-password
注意：命令中的 portainer_data 需要替换为你实际的数据卷名称。如果你当时安装时使用的就是 portainer_data，则无需修改。

查看新密码：命令成功运行后，终端会输出类似 Use the following password to login: <一串新密码> 的信息。记下这个新密码 。

重新启动 Portainer 容器：
docker start portainer
之后，你就可以使用用户名 admin 和这个新生成的密码登录了。登录后，你可以在 UI 界面的“My account”设置中将其修改为你更容易记住的密码 。
