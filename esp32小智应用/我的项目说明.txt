4、项目需求：
一、我的项目AI是一个可以通过语音对话，对话中如果有“开灯”、“打开电视”、“拉开窗帘”等词汇，esp32要通过 自定义UART向 Arduino Nano发送指令文本，Arduino Nano 接收到指令文本后再进行下一步处理。
二、由于人的语言的多样化，开灯的说法很多，我想建个语言命令和指令字符的对应数组，以上想加还可以随时补充，又能给Arduino Nano发送标准指令：
[["开灯","打开灯"],["open_led"]],
[["关灯","关闭灯","关上灯"],["close_led"]],
[["打开电视","开电视","看电视"],["open_tv"]],
[["关上电视","关闭电视","关电视","不看电视"],["close_tv"]],
[["拉开窗帘","打开窗帘","天亮了"],["open_cut"]],
[["拉上窗帘","关闭窗帘","天黑了"],["close_cut"]],........
三、Arduino Nano通过串口发给esp32文本，esp32当做对话给AI，同时能通过串口将AI回答的文本再反馈给Arduino Nano
注意串口传送的文本就半角字符还有全角的中文，所以你要考虑这个问题，不要出现乱码的问题。是否统一用UTF-8?你来设计方案。
建议思路：当AI接到对话时变成文本时，进行判断看里面有没有 语言命令 数组中的字串，如开灯、关灯等字串。如果有就不提交AI回答了，直接输出已开灯或已关灯。同时向串口发出open_led或close_led 指令字串。

我想这样实现：在 application.cc 中，控制用户语音文本日志输出（即 >> 你好。 这类日志）的代码段位于 OnIncomingJson 回调函数内处理 type 为 "stt" 的分支：
cpp
} else if (strcmp(type->valuestring, "stt") == 0) {
    auto text = cJSON_GetObjectItem(root, "text");
    if (cJSON_IsString(text)) {
        ESP_LOGI(TAG, ">> %s", text->valuestring);   // <-- 这就是需要的日志输出代码
        Schedule([display, message = std::string(text->valuestring)]() {
            display->SetChatMessage("user", message.c_str());
        });
    }
}

ESP_LOGI(TAG, ">> %s", text->valuestring);   在这段之前加上一段代码，用于检查用户语音文本中是否 有 语言命令 数组中的字串 ，如果有直接输出已开灯或已关灯。同时向串口发出open_led或close_led 指令字串。

即：
用户说“开灯” → 匹配到 open_led → 显示“已开灯”，串口发送 open_led\n，关闭音频通道，不再走 AI 对话。
用户说“今天天气怎么样” → 未匹配 → 正常显示用户文字，服务器继续处理并返回 AI 回答。

四、由于我的项目的特殊需求，所以要求AI不能休眠，一是开机不需要按 boot 键就进入聆听状态，第二要随时要听对话，需要随时保持聆听状态，不能说goodbey，但这里要注意别整的死循环了，只显示聆听，但聆听不了，发生麦克不起作用的问题。

小智的逻辑好像是进入聆听状态后同时打开麦克，如果只进入聆听状态不打开麦克,麦克不工作。

编译与烧录步骤
设置目标芯片：
bash
idf.py set-target esp32

配置项目：
bash
idf.py menuconfig
进入 Xiaozhi Assistant → Board Type，选择 My ESP32 Board (双核 ESP32 + OLED 优化引脚)。

清理并构建：
bash
idf.py clean
idf.py build

idf.py fullclean
idf.py build

烧录并监视：
bash
idf.py erase_flash
idf.py -p COM7 flash monitor

验证 OLED 显示：上电后屏幕应显示 "XiaoZhi AI Ready"，配网或配对时验证码会显示在屏幕上。
